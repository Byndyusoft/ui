# Design

## Context

Текущая реализация фабрик находится в `components/view/src/createView.tsx` и
`components/flex/src/createFlex.tsx`. `View` маппит spacing-пропсы, удаляя их из
объекта `props` мутацией; `Flex` деструктурирует свои пропсы, но дублирует
`blockClassName` и использует `classnames` отдельно от `View`. Обе фабрики
вызывают `registerLayoutStyles` при создании компонента и возвращают компоненты
через `Object.assign` с `config`. Публичные экспорты ограничены factory и
основными типами. См. `proposal.md` для мотивации.

Ограничения: React 17, TypeScript 4.9 strict, ESM-сборка Rollup, CommonJS не
требуется для этих пакетов. Публичное поведение и сгенерированный CSS должны
остаться идентичными.

## Goals / Non-Goals

**Goals:**
- Устранить мутацию пропсов и несогласованную сборку `className`.
- Убрать дублирование констант и CSS-утилит между `view` и `flex`.
- Сделать `displayName` и публичные экспорты предсказуемыми.
- Сохранить вывод типов и сгенерированный CSS побайтово совместимым.

**Non-Goals:**
- Изменение публичного API, типов spacing-пропсов или формата CSS-классов.
- Добавление новых компонентов, хуков или runtime-зависимостей.
- Миграция на React 18 API или изменение формата модулей.

## Decisions

- **Иммутабельная обработка пропсов.** В `View` spacing-пропсы деструктурируются
  отдельно от остальных пропсов, а в DOM передаётся новый объект без них. Это
  исключает мутацию входных данных и упрощает тестирование. Альтернатива —
  копирование объекта с `delete` — оставляет мутацию промежуточного объекта и
  менее прозрачна.

- **Единый источник `blockClassName`.** Константа `bsui-flex` экспортируется из
  `flexModifiers.ts` и переиспользуется в `createFlex.tsx`, вместо дублирования.
  Альтернатива — вынести в общий пакет — избыточна для одной строки.

- **Сборка `className` через `classnames`.** Оба компонента используют `cn` для
  детерминированного порядка и фильтрации пустых значений. Текущий `join` в
  `View` заменяется на `cn`, чтобы поведение с пустыми классами осталось тем же.
  Альтернатива — оставить `join` — сохраняет несогласованность и ручную фильтрацию.

- **`displayName`.** `CreatedView` → `'View'`, `CreatedFlex` → `'Flex'` для
  читаемости в DevTools и тестах. Имена фабрик при этом остаются `createView`/
  `createFlex`.

- **Расширение экспортов.** Из `view` дополнительно экспортируются
  `buildSpacingCss`, `spacingPropPrefixes`, `getSpacingClassName`,
  `spacingUnitVariable`, `validateGridKeys`. Из `flex` — `buildFlexCss`,
  `flexModifiersCss`, модификатор-хелперы, `blockClassName`, типы направлений
  и вариантов. Существующие экспорты сохраняются.

- **Именование файлов и суффиксы.** Сохраняются принятые суффиксы
  `*.tests.*`, `*.tests-d.ts`, `*.ssr.tests.*`, `*.stories.*`; новые тесты и
  вспомогательные файлы именуются по сущности и роли (`Entity.tests.tsx`,
  `Entity.types.ts`). Проверяются исключения Rollup, чтобы тесты и истории не
  попали в `dist`.

- **Типы ref.** Компоненты остаются без `forwardRef` на этом этапе: добавление
  ref меняет публичный контракт и выходит за рамки рефакторинга. Если потребуется,
  это отдельное изменение. (Non-Goal)

## Risks / Trade-offs

- [Изменение порядка классов] → Тесты используют `toHaveClass` с exact-флагами;
  нужна проверка после замены `join` на `cn`.
- [Расширение экспортов] → Возможен рост публичного API; экспортируются только
  уже существующие утилиты, новые не добавляются.
- [Регрессия SSR] → Проверить `LayoutStyles` и registry-тесты после изменений.

## Migration Plan

1. Рефакторинг `view` без изменения экспортируемого поведения.
2. Рефакторинг `flex` с переиспользованием констант из `flexModifiers`.
3. Обновление `index.ts` обоих пакетов.
4. Запуск тестов, линтеров и сборки пакетов с зависимостями.
5. Добавление changeset `patch`.
