# Design

## Context

`IHttpResponse<T>` содержит `data?: T`; builder, адаптеры, executor и hooks уже используют этот общий интерфейс. Изменения его свойства достаточно для обновления публичных типов. Мотивация — в [proposal.md](./proposal.md).

## Goals / Non-Goals

**Goals:** убрать добавленную библиотекой необязательность, сохранив существующий generic API.

**Non-Goals:** гарантировать наличие тела в runtime, менять декодирование, вводить `.asNoContent()`, новые response-типы или проверки hooks.

## Decisions

### 1. Обязательное свойство существующего интерфейса

Заменить только объявление `data?: T` на `data: T`. Поля метаданных и параметр `T = unknown` сохраняются. Сигнатуры builder, адаптеров и executor продолжают использовать существующий `IHttpResponse<T>`.

```ts
const response = await client.get('/users/1').asJson<IUser>().execute();
response.data; // IUser
```

Не применять `NonNullable<T>`: явно заданный `IUser | undefined` должен остаться таким же. `unknown` сохраняет свою семантику. Для ожидаемого пустого результата потребитель может указать `void` в существующем `.asJson<void>()`; это только аннотация типа и не новый режим обработки.

Отдельная форма ответа без `data` и дополнительный generic builder не нужны для выбранного объёма изменения.

### 2. Доверие к типу без изменения runtime

Адаптеры продолжают возвращать `undefined` там, где возвращают его сейчас, в том числе для `204`, нулевой объявленной длины и пустого JSON. Новые ошибки или значения взамен пустого тела не добавляются. `asJson<IUser>()` не проверяет наличие тела или соответствие JSON типу `IUser`.

`HttpResponseError.data` и соглашение об `undefined` из error hooks сохраняются: это отдельные контракты. Типизированные fixtures и примеры адаптеров должны содержать `data`, соответствующее их generic; для пустого результата подходит `IHttpResponse<void>` с `data: undefined`.

Runtime-проверки из предыдущего варианта отклонены по согласованному сокращению объёма задачи.

## Risks / Trade-offs

-   Пустой ответ может фактически содержать `undefined`, несмотря на выбранный `T` → прямо описать в README, что generic задаётся потребителем и не валидируется.
-   Объекты ответа без `data` перестанут проходить TypeScript → обновить fixtures и описать миграцию: добавить поле с данными подходящего типа.

## Migration Plan

1. Изменить интерфейс, обновить затронутые fixtures и type-тесты; ожидания существующих runtime-тестов сохранить.
2. Обновить README и добавить changeset `minor` для текущей alpha-версии с описанием несовместимости типов. Версии и публикацию не выполнять.
3. Проверить тесты, линтер, форматирование и сборку пакета. Откат — возврат прежнего объявления свойства и связанных правок.
