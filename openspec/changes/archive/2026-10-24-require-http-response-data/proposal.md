# Proposal

## Why

Сейчас `IHttpResponse<T>` автоматически добавляет `undefined` к типу данных через `data?: T`. Потребитель должен иметь возможность задать тип ответа и работать с ним без этой дополнительной необязательности.

## What Changes

-   **BREAKING**: заменить `data?: T` на обязательное `data: T` в `IHttpResponse<T>`.
-   Сохранить явно заданные `T | undefined`, `void`, `null` и семантику `unknown`.
-   Обновить type-тесты, типизированные fixtures и документацию под обязательное поле.
-   Сохранить runtime-поведение: пустые ответы, разбор тела, ошибки и hooks работают как прежде. Новые методы builder и режимы ответа не вводятся.

## Capabilities

### New Capabilities

-   `http-response-body-contract`: публичный тип данных ответа соответствует выбранному типу без автоматически добавленной необязательности.

### Modified Capabilities

Нет: основные спецификации OpenSpec в проекте пока отсутствуют.

## Impact

Затронуты `IHttpResponse<T>`, использующие его type-тесты и fixtures, README и changeset пакета `@byndyusoft-ui/http-client`. Потребителям, создающим объекты ответа вручную, потребуется указывать `data`. Алгоритмы адаптеров и клиента, зависимости и набор экспортов сохраняются.
