# Design

## Context

`View` (`components/view`) маппит spacing-пропсы в CSS-классы, `Flex` (`components/flex`) рендерится через `View` и добавляет gap/flex-модификаторы. Сетка `su025`–`su1000` продублирована в четырёх местах: `View.types.ts` (TS-юнион), `spacing-units.scss` (переменные), `spaces.scss` (классы), `Flex.scss` (gap). Значения вычисляются от `--spacing-unit` на `:root`, что уже даёт рантайм-переопределение. Ограничения: React 17, TypeScript 4.9 (нет `const`-параметров дженериков TS 5.0 — нужен явный `as const` у конфига), сборка view — Rollup в ESM. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:**

- Конфигурация сетки (юнит + произвольные именованные токены) — данные проекта-потребителя, не код библиотеки.
- Один источник истины: типы props, имена классов и CSS выводятся из одного объекта конфигурации; рассинхрон невозможен конструктивно.
- Чистая разметка (классы, без inline-стилей), чистый CSS без препроцессоров.
- Доставка CSS целиком в рантайме: автоинъекция для SPA и стили в серверном HTML для SSR — без build-time пайплайна у потребителя.

**Non-Goals:**

- Изменение существующих `View`/`Flex`/`TSpacingUnit` и классовой схемы `su*` — они остаются как есть.
- Общая система тем (цвета, радиусы, типографика) — только отступы и gap.
- Escape hatch для значений вне сетки — не делаем в MVP; добавится минором при появлении реального кейса.
- Build-time генерация CSS-файлов (строка наружу, рецепт-скрипт, CLI) — осознанно отложена: чистый генератор оставляет возможность добавить позже без ломки API.
- Метапакет-«зонтик» (`@byndyusoft-ui/scaffold`) — имя зарезервировано на будущее, в этой задаче не создаётся.
- Миграция `styles/css-utilities` и `Flex.scss` с SCSS на генератор — отдельная задача (dogfooding).

## Decisions

### 1. Фабрики с выводом типов из конфига, без кодогенерации

`createView(config)` — дженерик-функция: литеральный тип конфига становится параметром `T`, типы spacing-пропсов вычисляются как `keyof T['grid']`. Конфиг требует `as const` (TS 4.9).

Альтернативы и почему отклонены:

- **Кодогенерация типов и CSS из конфига** — решает рассинхрон внутри библиотеки, но сетка остаётся зашитой в опубликованный пакет; потребитель не может задать свою.
- **Declaration merging** (`interface IViewSpacingGrid`) — типы расширяются, но нельзя сузить сетку, а CSS под новые токены потребителю писать руками; два источника истины.
- **Числа-множители с inline-стилями** — отклонено пользователем: раздувает разметку и ломает каскад.

### 2. `createFlex(view)` — конфигурация путешествует с компонентом

`createView` возвращает компонент с прицепленной конфигурацией (статическое поле + брендированный тип). `createFlex` принимает этот экземпляр и выводит сетку из его типа — потребитель указывает конфигурацию один раз, рассинхрон между View и Flex исключён. Это зеркалит рантайм-устройство: Flex и сейчас рендерится через View.

Альтернативы: передача одного конфига в обе фабрики (риск расхождения в коде потребителя); единый пакет с `createLayout(config)` (отклонён при обсуждении — сохраняем пакеты и имена, имя `scaffold` приберегается для зонтика).

### 3. CSS генерирует JS-функция, классы вместо inline-стилей

Чистая функция `buildSpacingCss(config)` (в пакете view) пробегает по `grid` и собирает плоский CSS: матрица `m/p × стороны × токены` для view, gap-классы для flex. SCSS из нового пути исключён — «цикл» живёт в JS. Фиксированные flex-модификаторы (direction/wrap/align/justify) не зависят от сетки: пишутся один раз плоским CSS руками в пакете flex. Имена классов и маппинг пропсов в классы держатся за общие константы именования внутри пакета — генератор и рендер не могут разъехаться.

### 4. Юнит — CSS-переменная с фолбэком из конфига

Все значения генерируются как `calc(var(--bsui-unit, <unit>) * <multiplier>)`. Дефолт из конфига вшит как фолбэк; потребитель может переопределить переменную глобально, по медиа-запросу или на поддереве без пересоздания компонентов. Это сохраняет главное преимущество текущей схемы (`--spacing-unit`).

### 5. Доставка CSS: runtime-инъекция + компонент стилей для SSR

CSS собирается один раз при вызове фабрики. В браузере по умолчанию инъецируется в `<head>` — идемпотентно, реестр по ключу содержимого конфигурации: повторные вызовы фабрик и связка view+flex не дублируют стили. В node-окружении инъектор не обращается к DOM и не падает.

SSR закрывается без build-time пайплайна: библиотека экспортирует компонент стилей, рендерящий `<style>` со стабильным id и текстом сгенерированного CSS внутри дерева приложения. При `renderToString` стили попадают в HTML до гидратации (без FOUC); на клиенте инъектор распознаёт существующий элемент по ключу и пропускает вставку. Приём проверен экосистемой (styled-components, emotion `<Global/>`) и совместим с React 17.

Отвергнутая альтернатива — build-time генерация CSS-файла (строка наружу + рецепт-скрипт или CLI): требует от потребителя скрипт и дисциплину перегенерации файла при смене конфига, размывает разделение ответственности; осознанно отложена (см. Non-Goals).

### 6. Валидация ключей сетки ошибкой, не экранированием

Ключи проверяются при создании компонента; пробелы, точки, двоеточия и т.п. дают понятную ошибку с именем ключа. Экранированные CSS-классы нечитаемы и не нужны: цифровые ключи (`'025'`) легальны без экранирования, т.к. токен — сегмент внутри имени класса (`bsui-p-025`), а не его начало.

### 7. Размещение кода по существующим пакетам

`@byndyusoft-ui/view` владеет типами конфигурации, `buildSpacingCss`, инъектором, компонентом стилей и `createView`. `@byndyusoft-ui/flex` использует их через существующую зависимость на view и добавляет `createFlex` и gap-генерацию. Новые пакеты не создаются; публикация — `minor` обоих пакетов.

## Risks / Trade-offs

- [Конфиг без `as const` даст `string`/`number` вместо литералов, типизация сетки деградирует] → примеры в README и Storybook всегда с `as const`; рассмотреть сигнатуру, провоцирующую литеральный вывод.
- [Два разных конфига в одном приложении (микрофронты) дают коллизию классов: `bsui-p-md` с разными значениями] → реестр инъекций keyed по содержимому конфига; при конфликте одного класса с разными значениями — предупреждение в dev; задокументировать «одна сетка на страницу».
- [Гидратация дублирует стили, если инъектор не распознаёт серверный `<style>`] → дедупликация по ключу конфигурации и стабильному id; сценарий закреплён в спеке и задачах.
- [SSR-проект забыл добавить компонент стилей → стили появятся только на клиенте после гидратации (FOUC)] → безопасная деградация: приложение работает, стили доезжают инъекцией; задокументировать компонент как обязательный для SSR.
- [Рантайм-генерация CSS чуть увеличивает JS-бандл] → генератор — пара циклов и шаблонных строк; издержки несущественны против поставляемого сейчас CSS со ~1500 классами.
- [`createFlex(view)` связывает пакеты сильнее, чем раньше] → зависимость flex→view уже существует; контракт — публичное статическое поле компонента, покрытое типовыми тестами.

## Migration Plan

Миграция не требуется: API добавочный, `minor`-версии. Желающие переходят постепенно: создают `layout.ts` в проекте и переключают импорты на него; старые и новые компоненты сосуществуют. Откат — отказ от фабрик, на существующий код не влияет.
