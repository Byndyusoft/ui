# Design

## Context

Мотивация и область изменения описаны в [proposal.md](proposal.md), наблюдаемое поведение — в [спецификации text-editor](specs/text-editor/spec.md).

-   `components/text-area` и `components/text-input` задают названия отложенных callbacks, defaults 2000/1000 мс, независимость таймеров и разную очистку debounce/throttle. Их callbacks передают React-события; новый компонент передаёт строку Markdown.
-   `use-debounced-callback` и `use-throttled-callback` уже принимают generic tuple аргументов и предоставляют `cancel`/`flush`. Для throttle TextArea выбирает `leading: false`, `trailing: true`. Публичные hook API менять не требуется.
-   `useTextAreaAutoHeight` использует `rows`, `HTMLTextAreaElement.form` и измерение textarea. Его нельзя импортировать в другой workspace или непосредственно применять к contenteditable.
-   Root использует React 17, Rollup ESM для компонентов, Vitest/jsdom и Storybook 8.6. После обнаруженной несовместимости деклараций Tiptap с TS 4.9 пользователь разрешил обновить только сборочный TypeScript: закреплена версия 5.4.5, версии остальных зависимостей сохранены. Tiptap-пакеты закреплены на версии 3.32.0. Истории нового пакета подхватываются существующим glob.
-   SSR и гидратация исключены пользователем из первой версии после проверки ESM-импорта `@tiptap/react` с React 17. Node не разрешает его импорт `react/jsx-runtime`; клиентский bundler разрешает его. В клиентских тестах Vitest обрабатывает этот пакет через Vite.
-   До создания change рабочее дерево было чистым. Основных спецификаций OpenSpec и потребителей будущего пакета пока нет.

## Goals / Non-Goals

**Goals:**

-   Отделить полную модель документа от разрешений на пользовательские действия, чтобы `tools` не удалял сохранённые данные.
-   Изолировать Markdown-преобразование, ограничения команд, clipboard и жизненный цикл движка внутри нового пакета.
-   Сохранить знакомый API полей и временной контракт TextArea, не завязывая потребителей на типы движка.
-   Проверить движок с React 17 и сборочным TS 5.4.5 до основной реализации; отдельно сохранить потребление публичных деклараций TS 4.9 и проверить сохранение Markdown.

**Non-Goals:**

-   Извлечение общей реализации из TextArea/TextInput, изменение публичных хуков или глобальной конфигурации сборки.
-   Экспорт экземпляра движка, пользовательских extensions или произвольных команд: такой доступ обходит ограничения `tools`.
-   Побайтовое сохранение исходного Markdown, полноценный рендерер Markdown для сайтов или точное воспроизведение оформления Word/Google Docs.
-   Нативная constraint validation (`required`, `minLength`, `maxLength`) и адаптеры конкретных библиотек форм. `name`/`form` обеспечивают передачу значения и сброс; бизнес-валидация остаётся у формы.

## Decisions

### 1. Tiptap 3 с полной схемой и локальным Markdown-адаптером

Использовать Tiptap 3 на ProseMirror, React-интеграцию и `@tiptap/markdown`. Все поддерживаемые node/mark extensions регистрируются независимо от `tools`: document, text, paragraph, hardBreak, heading H1–H6, оба списка/listItem, bold, italic, underline, strike, link, история и placeholder. Подключать только требуемые расширения; при использовании StarterKit отключить лишние blockquote, code/codeBlock и horizontalRule. Схема и экземпляр редактора не пересоздаются при смене `tools`, callbacks или размеров.

Выбор обоснован готовой моделью документа, историей, выделением и двусторонним Markdown-преобразованием. Нативный contenteditable с ручным управлением выделением и историей существенно расширяет эту работу; прямой ProseMirror потребует отдельной системы команд и Markdown-адаптера; обычный Markdown textarea не обеспечивает согласованный визуальный ввод.

Первым шагом реализации выбрать и зафиксировать точные опубликованные совместимые версии Tiptap-пакетов одной линии. Проверить их peer dependencies, компиляцию с установленным TS 5.4.5, import/build и клиентское монтирование под React 17, а также round-trip каждого формата и их сочетаний. Не считать поддержку доказанной по `peerDependencies` и не скрывать несовместимость под `skipLibCheck`. Обновление существующих зависимостей разрешено только для TypeScript до 5.4.5; React и прочие версии остаются прежними. Если выбранная линия не удовлетворяет контракту, остановиться и обновить design с пользователем до основной реализации, а не менять движок или урезать форматы молча.

Проверка деклараций опубликованных линий Tiptap 3.7.0 и 3.32.0 с `skipLibCheck: false` не прошла на TS 4.9.5 (`NoInfer` и getter/setter `content`) и прошла на TS 5.4.5. Новый сборочный компилятор не повышает автоматически минимум для потребителя: публичные декларации компонента не должны тянуть типы движка и должны оставаться пригодными для TS 4.9. Эта граница проверяется отдельным consumer-fixture после появления публичного API. У текущего typescript-eslint 5.62 официальный диапазон ниже TS 5.2; установленная связка сохранена по условию пользователя, её фактическая работа проверяется общим lint.

Исследованные первичные источники:

-   [React peer dependencies Tiptap](https://github.com/ueberdosis/tiptap/blob/main/packages/react/package.json) включают React 17; это исходники main, а не доказательство совместимости выбранного npm-релиза.
-   [Markdown-модуль](https://tiptap.dev/docs/editor/markdown) предоставляет двустороннее преобразование и отмечен beta.
-   [Underline](https://github.com/ueberdosis/tiptap/blob/main/packages/extension-underline/src/underline.ts) уже разбирает и записывает `++…++`. Обработка буквальных плюсов, пробелов и смешанных marks всё равно требует регрессионных тестов.

### 2. Стабильный Markdown-контракт

Выделить локальные функции разбора, нормализации и сериализации. Диалект: поддерживаемое подмножество CommonMark, GFM strike `~~…~~` и underline `++…++`. Жирный записывать `**…**`, курсив `*…*`, заголовки ATX `#`–`######`, ненумерованные списки через `-`, нумерованные — с сохранением начального номера и порядка, ссылки через `[текст](адрес)`. Уровни вложенных списков, hardBreak и сочетания marks сохраняются семантически; экранирование различает служебные и буквальные символы. Пустой обычный абзац без содержимого нормализуется в `''`; пустые структурные блоки не удаляются только ради этой нормализации.

Внешние Markdown-значения разбираются полной схемой без фильтрации по `tools`. Неподдерживаемые структурные элементы по возможности преобразуются в текст и абзацы; неизвестное оформление не становится активным HTML. Не заявлять полную совместимость с произвольным GFM: изображения, таблицы и другие исключённые узлы не сохраняются как rich nodes. Документировать эту границу и необходимость поддержки `++…++` у потребителя отображения.

Использование HTML или JSON в публичном `value` отвергнуто в пользу выбранного пользователем Markdown. Одновременный экспорт нескольких форматов усложняет синхронизацию без требования пользователя.

### 3. Публичный API и defaults

`ITextEditorProps` базируется на `HTMLAttributes<HTMLDivElement>` с исключением конфликтующих `onChange`, `defaultValue`, `children`, `contentEditable` и `dangerouslySetInnerHTML`. Не переносить `TextareaHTMLAttributes`: `rows`, textarea events и нативный `disabled` неверно описывают редактируемую область. Экспортировать `ITextEditorProps`, `TTextEditorTool` через `src/index.ts`; типы движка остаются внутренними.

| API                                                                 | Контракт                                                                                           |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `value?: string`                                                    | Управляемый Markdown; определяется по `value !== undefined`                                        |
| `defaultValue?: string`                                             | Начальный неуправляемый Markdown, default `''`                                                     |
| `onChange?: (markdown: string) => void`                             | Немедленное изменение документа                                                                    |
| `onDebouncedChange?: (markdown: string) => void`                    | Последний снимок после паузы                                                                       |
| `debounceDelay?: number`                                            | Миллисекунды, default 2000                                                                         |
| `onThrottledChange?: (markdown: string) => void`                    | Последний снимок в конце окна                                                                      |
| `throttleDelay?: number`                                            | Миллисекунды, default 1000                                                                         |
| `tools?: ReadonlyArray<TTextEditorTool>`                            | Default `['bold', 'italic', 'underline', 'strike']`; `[]` скрывает панель                          |
| `withAutoHeight?: boolean`                                          | Default `false`, как TextArea; включение явно в примерах форм                                      |
| `isDisabled?: boolean`, `isReadOnly?: boolean`                      | Default `false`; disabled имеет приоритет                                                          |
| `placeholder?: string`                                              | Для пустого документа                                                                              |
| `name?: string`, `form?: string`                                    | Передача Markdown в FormData и привязка к форме по id                                              |
| `id`, `className`, `style`, `aria-*`, `data-*`, `onFocus`, `onBlur` | Применяются к фактической редактируемой области; style min/max-height ограничивает её, а не панель |
| `ref`                                                               | Object/callback ref на фактический редактируемый `HTMLDivElement`, без instance API движка         |

`TTextEditorTool` — union `'bold' | 'italic' | 'underline' | 'strike' | 'heading' | 'orderedList' | 'bulletList' | 'link'`. Уникальные инструменты отображаются в порядке первого вхождения. Абзацы и клавиатурные undo/redo не являются элементами `tools`; панель по умолчанию содержит ровно четыре согласованных инструмента.

Принятые уточнения для первой версии: все шесть уровней заголовков; `withAutoHeight=false` для согласованности с TextArea; className/style относятся к области ввода; именованные/default экспорты и DOM-ref повторяют соглашения пакетов. Переключение controlled/uncontrolled после монтирования не является поддерживаемым сценарием; README объясняет выбор одного режима.

### 4. `tools` ограничивает пути создания оформления

Держать актуальный набор разрешений в ref, который читают панель, shortcuts, input rules и link auto-detection. Использовать публичный механизм наследования extensions (`this.parent`), без обхода `StarterKit.config` и повторного построения встроенных keymaps. Штатные команды Tiptap выполняют редактирование; перехватывать только действия, ограниченные tools. Обычный Enter оставлять встроенным keymaps. Только при отключённых marks/heading/list применять специальный обработчик: штатные команды Tiptap выполняют разбиение; выход из отключённых списков использует небольшой мост к ProseMirror liftListItem. Этой команде нужна свежая транзакция, поскольку она применяет собственный mapping; цепочка нескольких split/lift на общем mapping ломает вложенные списки. Мост переносит только шаги lift и selection в общую транзакцию, сохраняя один callback и один undo без применения промежуточных состояний к редактору. Простое скрытие кнопок недостаточно; встроенные правила движка должны использовать те же проверки. Выбор `heading` разрешает H1–H6; `link` — создать, изменить и удалить ссылку без перехода по ней во время редактирования. Открытый интерфейс инструмента после его отключения больше не применяет команду.

Редактирование текста уже оформленного блока/фрагмента сохраняет его формат: `tools` не выполняет глобальную очистку документа. Это относится к обычному вводу внутри существующего фрагмента и восстановлению истории. Создание отдельного нового блока с отключённым типом запрещено: Enter после отключённого заголовка/списка создаёт обычный абзац. Новые команды не переносят отключённое оформление на другой диапазон.

Нельзя применять глобальный фильтр каждой транзакции или отключать extensions: оба подхода удаляют существующее оформление и ломают загрузку и undo/redo. Permissions применяются к конкретному действию, а не ко всему результату документа.

### 5. Одна фильтрация всех путей вставки

Буфер сначала преобразовать в документный fragment полной схемы: при наличии HTML использовать его структурированный разбор, иначе разбирать text/plain как поддерживаемый Markdown. Затем рекурсивно фильтровать fragment по актуальному `tools` и вставить его одной операцией истории. Встроенные paste rules/автолинкование не должны повторно добавлять снятые форматы.

-   Убирать недоступные inline marks, оставляя текст и доступные marks.
-   Недоступный heading превращать в paragraph; недоступную ссылку разворачивать в её видимый текст.
-   Недоступный тип списка разворачивать в отдельные абзацы для каждого элемента, сохраняя порядок. Вложенные разрешённые списки сохранять; запрещённые разворачивать рекурсивно.
-   Применять правила также к внутреннему clipboard fragment и к позиции с существующими недоступными marks. При вставке не наследовать такие marks и не менять окружение вне вставленного диапазона.

Сначала разбор, затем фильтрация сохраняет все разрешённые форматы. Преобразование всего буфера в plain text потеряло бы допустимое оформление. Фильтрация по DOM-тегам до разбора не покрывает внутреннее копирование и смешанные marks.

### 6. Синхронизация значения, уведомления и история

Один экземпляр движка хранит документ и выделение. На пользовательское изменение сериализовать Markdown сразу, обновить внутренний снимок и значение формы, запланировать оба отложенных уведомления, затем вызвать `onChange`. Порядок нужен для синхронного размонтирования внутри `onChange`, как в TextArea. Изменение выделения обновляет только активность панели.

Управляемый родитель обновляет `value` в немедленном `onChange`, а debounce/throttle используют для побочных действий. Сравнивать входное значение с текущим каноническим документом/последним снимком: обычный echo не вызывает `setContent`, не сбрасывает курсор, историю и таймеры. Настоящая внешняя замена выполняется без update callbacks, отменяет старые ожидания, обновляет высоту и начинает историю нового документа без возможности undo к заменённым данным. `defaultValue` читается только при инициализации и сбросе формы.

Внутренний `useTextEditorChangeCallbacks` повторяет временные правила TextArea через публичные хуки со строковым аргументом, layout-обновление актуальных callbacks, layout-flush debounce и layout-cancel throttle. Удаление обработчика отменяет его очередь, замена сохраняет срок; delays нормализуются по правилам TextArea. Переключение tools/states не отменяет уже корректно запланированное уведомление о предыдущем вводе. Cleanup debounce выполняется до уничтожения ресурса редактора, но не читает из него данные: строка уже сохранена.

Отличия от TextArea намеренные: строковый снимок не зависит от живого DOM; настоящая внешняя замена/сброс отменяет устаревшие уведомления. Не выносить новый общий публичный хук и не менять семантику существующих.

### 7. Размеры, DOM и серверный рендеринг

Панель и редактируемая область — отдельные узлы. Локальный `useTextEditorAutoHeight` измеряет только область ввода; использует её естественную высоту, CSS min/max-height, padding, border и box-sizing, без `rows`. События изменения документа/props/ширины объединяются в кадр; переносы заголовков и списков учитываются браузером. При достижении максимума прокручивается область, панель остаётся доступной. Сохранять DOM-узел и выделение между вводами, не перезаписывать HTML через React на каждый render.

Использовать изоморфные эффекты и публичный `useResizeObserver` там, где наблюдение нужно; иметь resize fallback при отсутствии API, исключить циклы по изменениям только высоты, пропускать скрытые измерения и пересчитывать после повторного отображения. При отключении восстановить актуальные пользовательские height/overflow/resize, отменить кадр и подписки. Отслеживание поздней загрузки шрифтов отдельно не включать; ограничение документировать, как у TextArea.

Движок создаётся только на клиенте (`immediatelyRender: false` у React-интеграции). Начальное содержимое появляется после клиентской инициализации без change callbacks. SSR и гидратация не входят в контракт первой версии по решению пользователя. Ref указывает на фактическую область после её появления и сбрасывается в null. Cleanup уничтожает instance, watchers, слушатели формы и таймеры; не использовать React 18+ API.

### 8. Форма, доступность и ссылки

При `name` скрытый input передаёт актуальную строку Markdown; его значение обновляется сразу при пользовательском вводе или внешнем `value`. `form` применяется к нему; disabled исключает input из отправки, read-only не исключает. Без `name` значение доступно через callbacks. Слушать reset актуальной связанной формы (внешней по id или ближайшей), пересвязывать подписку при изменении `form`. В uncontrolled сброс восстановит начальный defaultValue без change callbacks, в controlled сохранит value; оба отменяют ожидания и пересчитывают высоту.

Редактируемая область получает role textbox, aria-multiline и пользовательское доступное имя. Использовать aria-disabled/aria-readonly и реальный запрет editable; disabled исключает область/кнопки из Tab-порядка, read-only оставляет возможность фокуса/копирования. Кнопки панели имеют type button, доступные имена и aria-pressed, панель — клавиатурную навигацию. Сохранять selection при переходе на инструмент; для ссылки дать доступное поле URL и подтверждение/отмену с возвратом фокуса. Undo/redo выполняются клавиатурой. Специальная поддержка и проверки IME исключены пользователем; используется базовое поведение движка.

URL проверяется на всех входных путях: allowlist http/https/mailto/tel, относительные пути и фрагменты; отсеивать javascript/data и обходы через управляющие символы/кодирование. Не выполнять raw HTML из Markdown или буфера и не передавать пользовательский HTML в dangerouslySetInnerHTML; schema-based разбор и валидация атрибутов не заменяют защиту рендерера сайта при последующем отображении Markdown.

### 9. Упаковка и проверки

Новый пакет следует структуре text-area: ESM Rollup, src/index.ts, отдельные types, локальные hooks/utilities, README, CSS/SCSS и истории. Объявить runtime dependencies и React/ReactDOM peer dependencies, обновить корневой lock-файл через npm. Тесты, helpers, истории, MDX и `*.tests-d.ts` исключить из runtime и declarations. Не менять общие aliases/модульный формат; использовать существующую конфигурацию Storybook и точечно выявлять проблемы зависимостей.

Vitest проверяет Markdown и paste fixtures, компоненты/хуки, fake timers, ref, форму и состояния. Type tests импортируют публичную точку входа и проверяют строковые callbacks, tools, ref и отсутствие instance API. Реальный браузер в Storybook проверяет выделение, горячие клавиши, clipboard и измерения: jsdom не доказывает реальный layout и нативное редактирование. Сборка с зависимостями предшествует проверкам, если импорты идут через dist.

## Risks / Trade-offs

-   [Markdown-модуль beta; проверки деклараций TS 5.4.5 не доказывают весь runtime-контракт] → фиксация конкретной линии зависимостей, клиентская проверка и round-trip fixtures; отдельный тест публичных деклараций с TS 4.9. При неуспехе остановить реализацию до согласованного решения.
-   [Обход tools через встроенные shortcuts/input/paste rules или наследование marks] → один источник permissions и проверки каждого пути, включая смену tools без пересоздания instance и вставку внутри оформленного текста.
-   [Нормализация Markdown меняет исходное написание] → гарантировать смысл поддерживаемого документа, а не исходные пробелы/маркеры; экранирование и смешанные marks проверить отдельно.
-   [Отложенный callback при unmount может вызывать пользовательский код] → явно документировать контракт, хранить снимок, обновлять актуальный callback до очистки и тестировать синхронное размонтирование.
-   [HTML clipboard и ссылки] → разбирать только поддерживаемую структуру, валидировать URL и не исполнять HTML; фильтровать и внутреннюю вставку.
-   [Движок увеличивает размер пакета] → не включать необязательные extensions, не экспортировать движок в публичных типах, проверить ESM-выход и зависимости.
-   [SSR не поддерживается; поздняя загрузка шрифтов не отслеживается] → явно описать ограничения и проверить клиентскую инициализацию/обычный пересчёт.

## Migration Plan

Это новый opt-in пакет: существующие формы и импорты не мигрируются автоматически. Реализация добавляет пакет и minor changeset; выпуск версий и публикация выполняются отдельным релизным процессом. Примеры показывают импорт TextEditor, немедленное сохранение value, tools и явное withAutoHeight. При отказе от использования потребитель возвращается к прежнему полю; сохранённый Markdown остаётся строкой, его вывод должен поддерживать согласованный диалект.

## Open Questions

Конкретная совместимая опубликованная версия Tiptap-пакетов определяется ранней задачей проверки; архитектура и требуемое поведение от номера версии не меняются. В текущем этапе зависимости не устанавливались и runtime-прототип не создавался. Несовместимость является причиной остановки и пересмотра design, а не разрешением обновить весь монорепозиторий.
