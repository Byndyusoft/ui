# Spec Delta

## MODIFIED Requirements

### Requirement: Фабрика компонента раскладки из конфигурации сетки

Библиотека SHALL предоставлять фабрику, принимающую базовый шаг сетки и набор именованных токенов с числовыми множителями этого шага и возвращающую компонент раскладки View, который принимает spacing-пропсы (margin/padding и их варианты по сторонам).

#### Scenario: Создание компонента с проектной сеткой

-   **WHEN** потребитель вызывает фабрику с конфигурацией `{ step: { value: 8, unit: 'px' }, values: { sm: 0.5, md: 1, lg: 1.5 } }`
-   **THEN** возвращается компонент View, принимающий spacing-пропсы со значениями из ключей сетки (`'sm' | 'md' | 'lg'`)

#### Scenario: Имена токенов произвольны

-   **WHEN** потребитель задаёт в сетке ключи по своей схеме именования (например, `'025'`, `'gutter'`, `'s16'`)
-   **THEN** компонент принимает ровно эти имена как значения spacing-пропсов

#### Scenario: Допустимые значения шага

-   **WHEN** потребитель создаёт компонент с положительным целым `step.value` и `step.unit`, равным `'px'` или `'rem'`
-   **THEN** фабрика принимает конфигурацию

#### Scenario: Недопустимый шаг

-   **WHEN** потребитель создаёт компонент с неположительным или нецелым `step.value` либо с `step.unit`, отличным от `'px'` и `'rem'`
-   **THEN** TypeScript отклоняет неподдерживаемый тип единицы, а фабрика бросает понятную ошибку для недопустимых runtime-значений

### Requirement: Генерация CSS из конфигурации

Библиотека SHALL генерировать из конфигурации плоский CSS без препроцессоров: классы отступов для каждого токена и варианта стороны, классы gap для Flex и фиксированные классы flex-модификаторов. Значения отступов и gap MUST быть готовыми CSS-длинами, полученными умножением `step.value` на множитель токена с добавлением `step.unit`.

#### Scenario: Класс соответствует токену и множителю

-   **WHEN** конфигурация содержит токен `lg` с множителем `1.5` и шагом `{ value: 8, unit: 'px' }`
-   **THEN** сгенерированный CSS задаёт соответствующим свойствам значение `12px` без `calc()`

#### Scenario: Дробный множитель

-   **WHEN** конфигурация содержит токен с конечным дробным множителем `0.25` и шагом `{ value: 8, unit: 'rem' }`
-   **THEN** сгенерированный CSS задаёт соответствующим свойствам эквивалентную длину `2rem` без артефактов двоичной арифметики

#### Scenario: Разметка без inline-стилей

-   **WHEN** компонент рендерится со spacing-пропсами
-   **THEN** элемент получает только сгенерированные CSS-классы, атрибут `style` не используется

### Requirement: Компактное представление эффективных spacing-токенов

Компонент SHALL формировать непересекающийся минимальный набор spacing-классов из эффективных spacing-токенов. Стороны считаются одинаковыми только при совпадении имён токенов, а не только их числовых множителей.

#### Scenario: Все четыре стороны имеют одинаковый токен

-   **WHEN** эффективные токены всех четырёх сторон margin совпадают
-   **THEN** компонент добавляет один общий класс `<prefix>-m-<token>` вместо классов отдельных сторон

#### Scenario: Горизонтальная пара сворачивается в shorthand-класс

-   **WHEN** эффективные токены левой и правой сторон совпадают, а один общий токен не покрывает все четыре стороны
-   **THEN** компонент использует класс `mh` или `ph` с заданным префиксом и отдельные классы только для оставшихся заданных сторон

#### Scenario: Вертикальная пара сворачивается в shorthand-класс

-   **WHEN** эффективные токены верхней и нижней сторон совпадают, а один общий токен не покрывает все четыре стороны
-   **THEN** компонент использует класс `mv` или `pv` с заданным префиксом и отдельные классы только для оставшихся заданных сторон

#### Scenario: Все четыре стороны padding имеют одинаковый токен

-   **WHEN** эффективные токены всех четырёх сторон padding совпадают
-   **THEN** компонент добавляет один общий класс `<prefix>-p-<token>` вместо классов отдельных сторон

#### Scenario: Оставшиеся разные стороны

-   **WHEN** эффективные токены не образуют общего или парного shorthand-класса
-   **THEN** компонент добавляет классы с заданным префиксом для соответствующих физических сторон без изменения их вычисленных значений

#### Scenario: Совпадающие множители с разными токенами не схлопываются

-   **WHEN** эффективные токены сторон имеют разные имена, даже если их множители в `values` совпадают
-   **THEN** компонент не заменяет их общим или парным классом только на основании совпадения множителей

## REMOVED Requirements

### Requirement: Рантайм-переопределение юнита

**Reason**: Значение шага становится фиксированной частью конфигурации фабрики, а итоговые CSS-длины вычисляются при генерации CSS.
**Migration**: Чтобы изменить размеры отступов, передайте другое значение `step` при создании View и Flex; переопределение `--bsui-unit` больше не поддерживается.

## ADDED Requirements

### Requirement: Настраиваемый префикс CSS-классов

Фабрика View SHALL принимать необязательный `prefix` для классов View и связанных классов Flex. Если `prefix` не указан, SHALL использоваться `bsui`.

#### Scenario: Префикс по умолчанию

-   **WHEN** потребитель не указывает `prefix`
-   **THEN** сгенерированные классы сохраняют namespace `bsui` и совместимые имена классов

#### Scenario: Пользовательский префикс для View и Flex

-   **WHEN** потребитель создаёт View с `prefix: 'app'` и создаёт Flex из этого View
-   **THEN** spacing-классы View и gap-классы и модификаторы Flex используют namespace `app`

#### Scenario: Недопустимый префикс

-   **WHEN** потребитель задаёт пустой префикс или значение с символами, требующими CSS-экранирования
-   **THEN** фабрика бросает понятную ошибку при создании компонента
