# План развития нового TextArea

## Цель и ограничения

Добавить debounce-коллбек, throttle-коллбек и автоматическую высоту в `TextArea` на основе нативного `<textarea>`. Предыдущая реализация удалена из пакета вместе с её типами, экспортами, тестами и примерами.

Изменения компонента выполняем внутри пакета text-area. Дополнительно создаём пакеты `@byndyusoft-ui/use-debounced-callback` в `hooks/use-debounced-callback` и `@byndyusoft-ui/use-resize-observer` в `hooks/use-resize-observer`, переиспользуем существующие хуки. Остальные пакеты сохраняем без изменений. Стили компонента задаём внутри реализации; оформление Storybook сохраняем.

## Публичный API

Добавляем в `ITextAreaProps`:

| Пропс               | Тип                                       | Значение по умолчанию |
| ------------------- | ----------------------------------------- | --------------------- |
| `onDebouncedChange` | `ChangeEventHandler<HTMLTextAreaElement>` | отсутствует           |
| `debounceDelay`     | `number`, миллисекунды                    | `2000`                |
| `onThrottledChange` | `ChangeEventHandler<HTMLTextAreaElement>` | отсутствует           |
| `throttleDelay`     | `number`, миллисекунды                    | `1000`                |
| `withAutoHeight`    | `boolean`                                 | `false`               |

Два интервала независимы. Значения по умолчанию выбраны для плана: debounce — две секунды, throttle — одна секунда.

Поведение коллбеков:

-   Нативный `onChange` вызывается сразу при каждом пользовательском изменении.
-   `onDebouncedChange` вызывается после полной паузы `debounceDelay`. Каждое изменение перезапускает таймер. При размонтировании последнее ожидающее событие передаётся обработчику один раз.
-   `onThrottledChange` работает только с задержкой: первое изменение открывает окно `throttleDelay`, последующие заменяют ожидающее событие, сохраняя срок вызова. Следующее окно начинается с первого изменения после предыдущего вызова. При размонтировании ожидающий вызов отменяется.
-   Обработчики получают исходное событие. `target.value` отражает актуальное значение DOM при выполнении; `currentTarget` после синхронной обработки события уже недоступен.
-   Изменение `value` через пропсы пересчитывает высоту, но не запускает коллбеки.
-   Используется актуальный обработчик из пропсов. Изменение интервала применяется к следующему запуску таймера; существующий таймер сохраняет срок.
-   `0` означает асинхронный вызов через таймер. Отрицательные и нечисловые интервалы заменяются значениями по умолчанию.

## Этапы реализации

### 1. Пакет use-debounced-callback — P1

**Статус: выполнено.** Пакет создан; добавлены документация, пример Storybook и тесты поведения и типов.

Создать универсальный хук `useDebouncedCallback(callback, delay)` на базе `@byndyusoft-ui/use-timeout` и `@byndyusoft-ui/use-latest-ref`.

-   Хук принимает типизированный callback с произвольными аргументами и обязательный интервал в миллисекундах. Его реализация не зависит от DOM и React-событий.
-   Возвращать вызываемую функцию с методами `cancel(): void` и `flush(): void`.
-   Каждый вызов сохраняет последние аргументы и перезапускает таймер. По окончании задержки вызывать актуальный callback с последними аргументами.
-   `cancel()` отменяет таймер и очищает ожидающие аргументы. Последующий `flush()` ничего не вызывает.
-   `flush()` отменяет таймер и немедленно выполняет ожидающий callback ровно один раз. Перед выполнением очищать ожидающие аргументы; если вызова нет, ничего не делать.
-   По умолчанию при размонтировании отменять ожидание без вызова callback. Политику немедленного выполнения при размонтировании определяет использующий хук компонент.
-   При изменении интервала сохранять срок существующего таймера; новый интервал использовать при следующем вызове возвращённой функции. Интервал `0` сохраняет асинхронное выполнение через таймер.
-   Добавить экспорт, типы, зависимости, конфигурацию сборки, документацию, пример в Storybook и тесты по структуре существующих пакетов хуков.

### 2. Коллбеки TextArea — P1

**Статус: выполнено.** Локальный `useTextAreaChangeCallbacks` подключён к `TextArea`. Добавлены независимые интервалы, нормализация задержек, завершение debounce и отмена throttle при размонтировании. Тесты проверяют исходные React-события, актуальные обработчики и совместную работу с авто-высотой.

Вынести управление коллбеками в локальный хук пакета text-area.

-   Для debounce использовать новый `@byndyusoft-ui/use-debounced-callback`, передавая ему событие изменения и нормализованный `debounceDelay`.
-   При размонтировании TextArea вызывать `flush()` в cleanup layout-эффекта, до пассивной очистки хука. Так ожидающее событие выполняется до стандартной отмены debounce-хуком.
-   Для throttle использовать `@byndyusoft-ui/use-throttled-callback` с `{ leading: false, trailing: true }`.
-   Использовать `use-latest-ref` для актуальных обработчиков.
-   Регистрировать событие и запускать таймеры перед вызовом пользовательского `onChange`: синхронное размонтирование внутри него должно корректно завершать debounce.
-   Запускать соответствующий таймер только при наличии коллбека. Не передавать новые служебные пропсы в DOM.
-   Объявить зависимости на используемые хуки в пакете text-area.

### 3. Пакет use-resize-observer — P1

**Статус: выполнено.** Пакет создан; добавлены документация, примеры Storybook и тесты. Наблюдение за несколькими элементами проверено в браузере.

Создать универсальный хук `useResizeObserver(refs, onResize)` для наблюдения за размерами одного или нескольких DOM-элементов.

-   Принимать `refs: ReadonlyArray<RefObject<Element | null>>` и `onResize: (entries: Array<ResizeObserverEntry>) => void`. Хук не возвращает значение; пустой массив отключает все подписки. Для одного элемента передавать массив из одного ref.
-   Читать `ref.current` в layout-эффекте после каждого обновления DOM: отслеживать замену элементов при прежних refs, игнорировать пустые current и исключать дубликаты элементов. Изменение current без обновления компонента с хуком требует отдельного рендера для синхронизации.
-   Создавать один `ResizeObserver` на экземпляр хука и подписывать его на все переданные элементы с нативным режимом `content-box` по умолчанию.
-   Передавать массив записей об изменившихся элементах в актуальный callback через внутренний ref, сохраняя пакетную доставку нативного observer. Каждая запись содержит `target`, по которому потребитель определяет элемент; полный набор размеров всех наблюдаемых элементов хук не собирает.
-   Обновлять ref обработчика, подписки и очистку через `use-isomorphic-layout-effect`: в браузере до отрисовки, на сервере без выполнения эффектов и обращения к DOM.
-   При изменении состава элементов вызывать `observe()` только для добавленных и `unobserve()` для удалённых. Новый массив с теми же элементами или изменение их порядка не должны пересоздавать observer и повторять подписки.
-   Игнорировать записи для элементов, которые уже удалены из наблюдаемого набора. При размонтировании выполнять `disconnect()`.
-   При смене callback сохранять существующую подписку и использовать актуальный обработчик.
-   Поддерживать SSR и окружения без `ResizeObserver`: проверять доступность API, не создавать observer при его отсутствии и не обращаться к DOM во время серверного рендера.
-   Фильтрацию изменений ширины, расчёт высоты, объединение измерений через `requestAnimationFrame` и резервную подписку на изменение размера окна реализовать в использующем хук компоненте.
-   Добавить экспорт, типы, зависимости, конфигурацию сборки, документацию, примеры наблюдения за одним и несколькими элементами в Storybook и тесты по структуре существующих пакетов хуков.

### 4. Автоматическая высота — P1

**Статус: выполнено.** Локальный `useTextAreaAutoHeight` подключён к `TextArea` через `withAutoHeight`. Добавлены тесты хука, компонента и SSR; в браузере проверены оба `box-sizing`, CSS-ограничения, изменение ширины, сброс формы, скрытие и повторное отображение, выключение и повторное включение.

Вынести измерение и управление высотой в локальный хук `useTextAreaAutoHeight`.

-   При включённом флаге поле растёт и уменьшается по содержимому. `rows` задаёт минимальное число строк; без `rows` сохраняется нативный минимум — две строки.
-   CSS `minHeight` и `maxHeight` задают дополнительные ограничения. При достижении максимальной высоты появляется вертикальная прокрутка.
-   Перед измерением сбрасывать высоту в `auto`; рассчитывать итоговую высоту с учётом padding, border и `box-sizing`.
-   Пересчитывать высоту при первом отображении, пользовательском вводе, изменении `value`, `rows`, `style`, `className`, ширины поля и сбросе формы. Завершение загрузки шрифтов пока не отслеживать; ограничение описать в README.
-   Использовать `use-isomorphic-layout-effect`; размер поля отслеживать через новый `@byndyusoft-ui/use-resize-observer`. Передавать массив из ref поля только при включённой авто-высоте, иначе — пустой массив.
-   В `useTextAreaAutoHeight` находить в массиве `ResizeObserverEntry` запись текущего поля по `entry.target` и реагировать только на изменение его ширины, чтобы изменение высоты самим компонентом не запускало повторные измерения. Объединять измерения в один кадр через `requestAnimationFrame`.
-   При отсутствии `ResizeObserver` в `useTextAreaAutoHeight` использовать резервную подписку на событие изменения размера окна.
-   Объявить зависимость на `@byndyusoft-ui/use-resize-observer` в пакете text-area.
-   В режиме авто-высоты отключать ручное изменение размера. При выключении восстанавливать пользовательские `height`, `overflowY` и `resize`.
-   Сохранять DOM-элемент, фокус и выделение. Поддерживать внешний `ref`. При выключении и размонтировании удалять подписки и отменять запланированные измерения.

## Проверки и критерии готовности

-   **use-debounced-callback:** отсутствие немедленного вызова, перезапуск таймера, последние аргументы, актуальный callback, изменение интервала, асинхронная задержка `0`, отмена через `cancel()`, однократное выполнение через `flush()`, отсутствие повторного вызова по таймеру после `flush()`, отмена при размонтировании и сохранение типов аргументов.
-   **use-resize-observer:** наблюдение за одним и несколькими refs одним observer, пакетная передача массива `ResizeObserverEntry` с корректными `target`, игнорирование пустых current и дубликатов, первое монтирование обычного useRef, замена и удаление DOM-элемента при прежнем ref и массиве, отсутствие повторных подписок при новом массиве с тем же набором или изменении порядка, игнорирование записей удалённых элементов, актуальный callback без пересоздания observer, отключение при пустом массиве и размонтировании, SSR без чтения current и отсутствие `ResizeObserver`.
-   **Debounce:** перезапуск таймера, последнее событие, независимость от throttle, актуальный обработчик, однократный вызов при размонтировании.
-   **Throttle:** отсутствие немедленного вызова, последнее событие внутри окна, непрерывный ввод, граница интервала, отсутствие вызовов после размонтирования.
-   **Авто-высота:** controlled/uncontrolled-режимы, рост и уменьшение, `rows`, сброс формы, изменение ширины, игнорирование изменений только высоты, объединение измерений в один кадр, резервная подписка на изменение размера окна, выключение флага, очистка ресурсов.
-   **В браузере:** оба варианта `box-sizing`, padding и border, CSS-ограничения высоты, прокрутка, скрытие и повторное отображение поля.
-   **Совместимость:** нативные атрибуты, `isDisabled` и `ref`.
-   **Завершение:** сборка text-area и обоих новых пакетов хуков, проверка типов, проверки исходников и открытие новых примеров в Storybook проходят.

## Доработка после ревью throttle

**Статус: выполнено.** В `use-throttled-callback` исправлены минимальный интервал между вызовами, вложенные вызовы, восстановление после исключений и очистка аргументов при отключении trailing. Добавлены `cancel()`, `flush()`, именованный экспорт и русская документация.

В `use-throttled-value` setter поддерживает функции обновления состояния и управление ожиданием. В `TextArea` удаление отложенного обработчика отменяет его событие и таймер; повторное включение не восстанавливает старое событие. Throttle отменяется в layout-фазе размонтирования. Режим TextArea остаётся `leading: false, trailing: true`.

Подготовлен выпуск throttle-хуков версии `0.3.0`. Публикация `text-area` отложена до готовности компонента: пакет помечен как `private: true` и исключён из обновления версий через `.changeset/config.json`. Подготовка релиза проверена на временной копии: версия и changelog `text-area` не меняются, его зависимость `@byndyusoft-ui/use-throttled-callback` автоматически обновляется до `^0.3.0`. Перед выпуском `text-area` нужно убрать эти ограничения и создать отдельный Changeset. Архивы пакетов содержат только README, package.json, код и типы из dist. Оформление Storybook сохранено.
