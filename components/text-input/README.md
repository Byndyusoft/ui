# `@byndyusoft-ui/text-input`

React-компонент на основе нативного `<input>` с двумя видами отложенных коллбеков. Тип поля по умолчанию — `text`.

## Установка

```sh
npm install @byndyusoft-ui/text-input
```

## Использование

```tsx
import React, { useState } from 'react';
import TextInput from '@byndyusoft-ui/text-input';

const Example = (): JSX.Element => {
    const [value, setValue] = useState('');

    return (
        <TextInput
            aria-label="Название"
            value={value}
            onChange={event => setValue(event.target.value)}
            onDebouncedChange={event => console.log('После паузы:', event.target.value)}
            debounceDelay={600}
            onThrottledChange={event => console.log('С ограничением частоты:', event.target.value)}
            throttleDelay={400}
        />
    );
};
```

Компонент поддерживает управляемый режим через `value` и обычный режим через `defaultValue`. Нативные атрибуты и обработчики передаются в DOM. Через `ref` доступен `HTMLInputElement`; оформление задаётся через `style` и `className`.

Доступны экспорт по умолчанию, именованный экспорт `TextInput` и тип `ITextInputProps`.

## Пропсы

| Пропс               | Тип                                    | По умолчанию | Поведение                                                |
| ------------------- | -------------------------------------- | ------------ | -------------------------------------------------------- |
| `type`              | `HTMLInputTypeAttribute`               | `text`       | Нативный тип поля ввода.                                 |
| `isDisabled`        | `boolean`                              | `false`      | Устанавливает нативный `disabled`.                       |
| `onChange`          | `ChangeEventHandler<HTMLInputElement>` | отсутствует  | Вызывается сразу при пользовательском изменении.         |
| `onDebouncedChange` | `ChangeEventHandler<HTMLInputElement>` | отсутствует  | Вызывается после полной паузы во вводе.                  |
| `debounceDelay`     | `number`                               | `2000`       | Длительность паузы в миллисекундах.                      |
| `onThrottledChange` | `ChangeEventHandler<HTMLInputElement>` | отсутствует  | Вызывается с задержкой, не чаще одного раза за интервал. |
| `throttleDelay`     | `number`                               | `1000`       | Интервал ограничения частоты в миллисекундах.            |

Вместо нативного пропса `disabled` используется `isDisabled`.

## Коллбеки

### После паузы: debounce

Каждое пользовательское изменение сохраняет последнее событие и перезапускает таймер. `onDebouncedChange` выполняется, когда ввод прекратился на весь `debounceDelay`.

При размонтировании последнее ожидающее событие передаётся обработчику один раз, без ожидания оставшегося времени. Если ожидания нет, обработчик не вызывается.

### Ограничение частоты: throttle

Первое изменение запускает окно `throttleDelay`; немедленного вызова нет. Следующие изменения заменяют ожидающее событие, сохраняя срок окна. В конце окна `onThrottledChange` получает последнее событие.

Новое окно начинается с первого изменения после предыдущего вызова. Поэтому непрерывный ввод вызывает обработчик не чаще одного раза за интервал. При размонтировании ожидание отменяется.

### Общие правила

-   Интервалы независимы; оба коллбека можно использовать одновременно.
-   `onChange` сохраняет нативное поведение и вызывается сразу. Ожидания регистрируются до него, поэтому синхронное размонтирование внутри `onChange` завершает debounce и отменяет throttle.
-   Без соответствующего отложенного обработчика новый таймер для него не запускается.
-   Удаление отложенного обработчика отменяет его таймер и ожидающее событие. Повторное включение не восстанавливает старое событие. Замена одного обработчика другим сохраняет срок ожидания и использует актуальную функцию.
-   Изменение `value` через пропсы не запускает коллбеки.
-   Ожидающий вызов использует актуальный обработчик из пропсов. Изменение интервала сохраняет срок текущего таймера; новый интервал используется при следующем запуске.
-   Задержка `0` означает асинхронный вызов через таймер. Отрицательные, бесконечные и нечисловые значения заменяются значениями по умолчанию.

Все обработчики получают исходное React-событие. Оно сохраняется по ссылке: `event.target.value` отражает значение DOM на момент выполнения, включая программные изменения после ввода. После завершения синхронного обработчика `event.currentTarget` становится `null`. Для сохранения значения именно на момент ввода скопируйте строку внутри `onChange`.

Поддержка серверного рендеринга пока не рассматривается; этот сценарий планируется реализовать позже.
