# Пакеты хуков

Следуй корневому [AGENTS.md](../../../AGENTS.md). Для generic и публичных типов
используй [fe-typescript](../fe-typescript/SKILL.md), для имён —
[fe-naming](../fe-naming/SKILL.md), когда это нужно задаче.

## Структура и контракт

-   Публичный пакет располагается в `hooks/use-<kebab-case>` с именем
    `@byndyusoft-ui/use-<kebab-case>`; реализация — `src/useCamelCase.ts`.
-   Обычные файлы: `package.json`, README, `tsconfig.json`, `tsconfig.build.json`,
    `src/index.ts`, реализация и `*.tests.ts`/`*.tests.tsx`.
    Связанные публичные типы могут лежать в `*.types.ts`, истории/MDX — в `src/__stories__`.
    Небольшие внутренние типы могут оставаться в файле хука.
-   Сохраняй существующую форму результата: значение, tuple, объект методов или callable
    с методами. Не заменяй форму на другую ради единообразия.
-   Для нового API определи значение по умолчанию, единицы времени, форму начального значения,
    реакцию на смену параметров и поведение после unmount. Документируй только применимые пункты.
-   Публичные generic должны сохранять типы аргументов и результата; экспортируй необходимые
    контракты через `src/index.ts`. Именованные и default-экспорты сохраняй при изменениях.
-   Общую логику сначала ищи в существующих пакетах. Используй публичные workspace-импорты
    и объявляй зависимости в манифесте.

## Состояние, callbacks и подписки

-   Вызывай React-хуки без условий. Не создавай подписки, observer или таймеры в теле render.
-   Когда новое состояние зависит от предыдущего, используй функциональное обновление,
    например `setValue(previousValue => ...)`.
-   Для императивных ресурсов и данных, которые не должны вызывать render, используй ref.
    Не используй ref вместо state, если изменение должно обновлять отображение.
-   Отложенный вызов должен получать актуальный callback согласно контракту.
    Используй существующий `useLatestRef` или подходящее обновление ref в эффекте,
    проверив, в какой фазе должен стать доступен новый callback.
-   Разделяй изменение callback и параметров подписки: смена callback не всегда требует
    пересоздания observer или таймера. Не скрывай реально нужные зависимости эффекта.
-   Стабильность возвращаемой функции обеспечивай, когда она нужна потребителям или контракту.
    Не добавляй `useMemo` и `useCallback` ко всем значениям автоматически.
-   Эффект должен освобождать созданный ресурс: удалять listener с совместимыми параметрами,
    останавливать таймер или отключать observer. Учитывай повторную установку эффекта.
-   Для DOM-ref учитывай смену `ref.current` при прежнем объекте ref: зависимость `[ref]`
    не гарантирует повторную подписку на новый элемент. В некоторых хуках потребуется
    callback-ref, элемент в state или синхронизация после render.
-   Для observer отбрасывай уведомления от уже снятых элементов или старого observer,
    если они могут приходить после смены подписки.
-   Для таймеров определяй отмену/завершение ожидающего вызова, смену delay и повторные вызовы.
    `cancel`, `flush`, `leading`, `trailing` добавляй только если они нужны API.

## SSR и примеры

-   Для DOM-хуков учитывай SSR без `window`/`document` и отсутствие необязательных browser API.
    Инициализаторы state и вычисления в render также выполняются на сервере.
-   Для DOM-работы до paint используй существующий `use-isomorphic-layout-effect`,
    когда layout-фаза требуется поведению; обычным подпискам может быть достаточно `useEffect`.
-   Образцы выбирай по задаче:
    [useDebouncedCallback](../../../hooks/use-debounced-callback/src/useDebouncedCallback.ts)
    — callback с методами и таймером;
    [useResizeObserver](../../../hooks/use-resize-observer/src/useResizeObserver.ts)
    — смена элементов, актуальный callback и очистка;
    [useArray](../../../hooks/use-array/src/useArray.ts) — generic tuple и команды состояния.
    Старые DOM-хуки не считай автоматически образцом SSR-безопасности.

## Проверка и сборка

-   Используй Vitest, `renderHook` и `act` из `@testing-library/react-hooks`.
    Проверяй поведение на первом render, rerender со сменой параметров и unmount,
    выбирая случаи по контракту хука.
-   Для таймеров используй `vi.useFakeTimers`, проверяй границы задержки без реального ожидания
    и восстанавливай таймеры после теста. Для browser API восстанавливай mock и globals.
-   SSR-тесты выполняй с `// @vitest-environment node` через `renderToString`.
    Проверяй отсутствие доступа к DOM и неожиданных callback на сервере.
-   Для generic API добавляй `*.tests-d.ts` по `fe-typescript`.
-   Обычно сборка запускает `tsc --project tsconfig.build.json`; некоторые старые пакеты
    используют `tsc` и CommonJS. Сохраняй формат пакета и исключай тесты/истории из `dist`.
-   Из корня, например:

```sh
npm test -- hooks/use-debounced-callback/src
npm run lint:check --workspace=@byndyusoft-ui/use-debounced-callback
npx --no-install turbo run build --filter='@byndyusoft-ui/use-debounced-callback...'
```

Проверяй скрипты выбранного пакета: не у всех хуков есть `lint:check` и `test`.
Для выборочных тестов используй корневой фильтр пути, а не предполагаемый `--project`.
Обновляй README, истории/MDX для пользовательского поведения и changeset для публикуемых изменений.
